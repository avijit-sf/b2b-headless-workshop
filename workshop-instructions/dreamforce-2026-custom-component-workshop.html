Before You Begin — What's Already Set Up

In the previous workshop you deployed a B2B Commerce headless React storefront. In this session you'll add a custom inventory availability component to the product detail page (PDP) — using Agentforce Vibes to write and deploy the React code for you.

Your workshop org has been pre-configured with everything the component needs. You will not write any Apex or touch permissions — you only build the front-end component.

Inventory Apex Class

An Apex REST class that fetches live inventory from Salesforce Order Management (OMS). It lives under /workshop/inventory and exposes GET /services/apexrest/inventory/availability?productId=.

Agentforce Vibes Skill

A pre-installed skill under .afv/skills/commerce-b2b-workshop-inventory that teaches the agent how to call the Apex class from a React component.

Buyer Permissions

Your buyer user already has the UIBundleApexAccess permission, so the storefront is allowed to invoke the Apex endpoint. No permission changes are needed.

A Deployed Storefront

A published headless storefront with product detail pages (from the deployment workshop) that you can browse and refresh.

❗
Do not change the Apex class or permission sets. They are already correct. This workshop only adds a React component that calls the existing endpoint.

Step 1

Build the Availability Component

Give Agentforce Vibes one prompt and let it generate the React inventory component for the product detail page.

1
Build the Availability Component

Open the Agentforce Vibes chat in your storefront project and submit the prompt below. It tells the agent exactly what to build and how it should look and behave.

1
Click into the Agentforce Vibes chat input field at the bottom of the chat panel.
2
Copy and paste the following prompt exactly, then press Enter:
Prompt
Your org already has GET /services/apexrest/inventory/availability?productId= and your buyer has UIBundleApexAccess. Add a React availability component on the product detail page that calls it with the current product id. Show a colored bullet, the on-hand quantity in bold, and bold colored IN STOCK (green) or OUT OF STOCK (red). Below that, add a dropdown “Show Inventory Across All Locations” with comfortable spacing listing each location’s name and the same bullet / quantity / status. Use the Apex URL (not /commerce/webstores/...). On error, show “Availability unavailable”; do not crash the page. Do not change Apex or permission sets.

What the agent will build

  • A component on the PDP that calls the Apex endpoint with the current product id.
  • A colored bullet, the on-hand quantity in bold, and a bold IN STOCK / OUT OF STOCK label.
  • A “Show Inventory Across All Locations” dropdown that lists each location with its own bullet, quantity, and status.
  • Graceful error handling — it shows “Availability unavailable” instead of crashing the page.
⚠️
Watch the URL. The component must call the Apex REST URL /services/apexrest/inventory/availability — not a /commerce/webstores/... URL. If the agent generates the wrong URL, tell it: “Use the Apex REST URL, not the webstores API.”

Reference

Troubleshooting

Common issues and quick fixes if your component doesn't appear or behave as expected.

⚑
Troubleshooting
SymptomLikely cause & fix
Component doesn't appear on the PDP The browser is serving a cached bundle. Hard refresh again (Cmd/Ctrl + Shift + R), or open the PDP in a private/incognito window. Confirm the agent reported a successful deploy.
Shows “Availability unavailable” The component called the endpoint but got an error. Verify it uses /services/apexrest/inventory/availability?productId= (the Apex URL, not /commerce/webstores/...). Re-prompt the agent to fix the URL, then rebuild and redeploy the bundle.
Wrong URL was generated Tell the agent: “Use the Apex REST URL /services/apexrest/inventory/availability, not the webstores API,” then run the build & deploy prompt again.
Permission / 401 / 403 error The buyer needs the UIBundleApexAccess permission — it is pre-assigned in your workshop org. Do not change permission sets yourself; ask your workshop instructor for help if the error persists.
Quantities show 0 for every location That product may have no OMS inventory loaded. Try a different product's PDP (e.g. the reference battery). Zeros correctly render as red OUT OF STOCK — that's expected behavior, not a bug.
Build or deploy fails Read the error in the chat and ask the agent to retry: “The build failed with this error — please fix it and redeploy the bundle.” Ensure you deployed to your default org.
Old version keeps showing Clear the site cache: hard refresh, try incognito, or append ?cache=0 to the PDP URL. Confirm the latest bundle actually deployed (re-run the deploy prompt).
Dropdown looks cramped Re-prompt the agent: “Add comfortable spacing between location rows in the availability dropdown,” then rebuild and redeploy.
💡
When in doubt, ask the agent. Paste the exact error or describe what you see and ask Agentforce Vibes to diagnose and fix it — then rebuild and redeploy the bundle.
