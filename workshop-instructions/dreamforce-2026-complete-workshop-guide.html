1 Deploy the Headless Storefront with Agentforce Vibes

Build and deploy a modern React-powered headless storefront using AI-assisted development — right from your Salesforce org. Agentforce Vibes handles the heavy lifting: you clone the repo, add a deployment skill, and run one prompt.

Before you begin

Make sure you have the following ready before starting the workshop.

Salesforce Org

A Salesforce org with B2B Commerce enabled and Agentforce Vibes available. Your workshop org has been pre-configured.

Web Browser

Google Chrome or Microsoft Edge (latest version recommended). Safari and Firefox may have limited compatibility.

GitHub Repository

We'll clone the open-source storefront from github.com/trailheadapps/commerce-b2b-headless.

Time Required

Approximately 30–45 minutes to complete all steps. The AI agent handles most of the heavy lifting!

💡

Tip: Agentforce Vibes is now built right into your Salesforce org — no setup or installation needed. Just open it from the Setup Gear Menu and start building.

1.1 Access Agentforce Vibes

Agentforce Vibes is now native to your Salesforce org. You can launch it directly from the Setup Gear Menu.

  1. Log into your Salesforce org. You'll land on the Lightning home page.
  2. Click the Setup Gear icon (⚙️) in the top-right corner of the navigation bar.
  3. From the dropdown menu, click Agentforce Vibes. This opens the IDE in a new tab.
  4. When prompted with “Do you trust the authors of the files in this folder?”, click Yes, I trust the authors to enable all features.
💡

Tip: If you don't see “Agentforce Vibes” in the gear menu, navigate to Setup → Development → Agentforce Vibes IDE to verify it's enabled.

1.2 Move Chat to the Right-Side Panel

For the best workflow, we recommend moving the Agentforce Vibes chat panel to the right side of the IDE so you can see both the file explorer and the chat simultaneously.

  1. In the left sidebar, locate the Agentforce Vibes icon (it looks like a robot head — 🤖). Click it to open the chat panel.
  2. Right-click the “AGENTFORCE VIBES” header text at the top of the chat panel.
  3. Select Move Views to Secondary Side Bar from the context menu.
  4. The chat panel now appears on the right side of the IDE, giving you a side-by-side view of the file explorer (left) and chat (right).
💡

Tip: You can also use the keyboard shortcut Ctrl+Alt+B (or Cmd+Alt+B on Mac) to toggle the secondary side bar on and off.

1.3 Clone the Repository

Now we'll use the Agentforce Vibes chat to clone the open-source B2B Commerce headless storefront repository.

  1. Click into the Agentforce Vibes chat input field (at the bottom of the chat panel).
  2. Type (or copy-paste) the following prompt:
    ● Clone prompt
    Clone https://github.com/trailheadapps/commerce-b2b-headless at /home/codebuilder/
  3. Press Enter (or click the send button) to submit the prompt.
  4. Wait for the agent to clone the repository. You'll see progress messages in the chat as the repo is downloaded.
💡

Tip: The cloning process typically takes 30–60 seconds depending on network speed. The agent will confirm when it's complete.

1.4 Change the Project Folder

After cloning, you need to switch the IDE workspace to the new commerce-b2b-headless project folder.

  1. Look at the top of the IDE window — you'll see the current folder name (e.g., “dx-project”) displayed in the title bar.
  2. Click File → Open Folder... from the top menu bar (or press Ctrl+K, Ctrl+O).
  3. In the folder picker, navigate to: /home/codebuilder/commerce-b2b-headless
  4. Click OK to open the folder. The IDE will reload with the storefront project.
  5. If prompted to trust the folder authors again, click Yes, I trust the authors.
⚠️

Important: Make sure you are in the commerce-b2b-headless folder before proceeding to the next step. The file explorer on the left should show folders like force-app, scripts, and files like sfdx-project.json.

1.5 Create the Skills Folder & Add the Skill

The Agentforce Vibes agent uses skills — pre-built instruction sets that teach the agent how to perform specific tasks. We need to add the deployment skill to our workspace.

Create the skills directory

  1. In the file explorer, right-click in the root of the project and select New Folder.
  2. Name it .afv (with the leading dot). Inside it, create another folder called skills.

Your folder structure should now include: .afv/skills/

Copy the deployment skill

  1. Copy the commerce-b2b-headless-setup-deploy/ folder (provided by your workshop instructor) into the .afv/skills/ directory.
  2. If the skill doesn't appear immediately, reload the window: press Ctrl+Shift+P (or Cmd+Shift+P on Mac), type “Reload Window”, and select it.

Enable the skill

  1. Open the Agentforce Vibes chat panel and click the Toolkit button (or gear icon).
  2. Navigate to Skills and toggle ON the commerce-b2b-headless-setup-deploy skill.
❗

Do NOT use “+ Add Skill” for this one. That UI creates a single SKILL.md file and will miss the references/deploy-commands.md file that the skill needs. You must manually copy the entire folder as described above.

1.6 Run the Deployment Prompt

Now comes the exciting part — let the AI agent deploy the entire storefront for you!

  1. Click into the Agentforce Vibes chat input field.
  2. Type (or copy-paste) the following prompt:
    ● Deployment prompt
    Use commerce-b2b-headless-setup-deploy skill to deploy B2B Commerce headless storefront
  3. Press Enter to submit. The agent will begin the multi-step deployment process.

The agent will automatically:

  • Configure your org's WebStore ID, Buyer Group, and Permission Set Group
  • Install all Node.js dependencies
  • Build the React application with Vite
  • Deploy Apex classes, UIBundles, and Experience Cloud site metadata
  • Set up guest user permissions
  • Publish the site
💡

Tip: The full deployment typically takes 5–10 minutes. You can watch the agent's progress in real-time as it runs commands and reports status updates in the chat.

1.7 Continue to Hit Run

During the deployment process, the agent may pause at certain stages and ask for your confirmation before proceeding. This is normal behavior.

  1. When the agent pauses, you'll see a Run button appear in the chat. Click it to continue.
  2. Repeat this for each pause — the agent may stop 3–5 times during the full deployment.
  3. When the deployment is complete, the agent will confirm with a success message and provide the URL to your new storefront.
⚠️

If something fails: Don't worry! Read the error message in the chat, and ask the agent to try again or troubleshoot the issue. The agent can usually fix most problems on its own.

✅ Deployment complete! Your headless React storefront is live — you can browse products, test the cart, and explore the full B2B commerce experience. Next, build the search index so products appear.

2 Set Up the Search Index So Products Appear

Run a full search index update in Commerce so buyers can browse and search products in your newly deployed B2B storefront.

Before you begin — why this step matters

You've deployed your B2B Commerce headless React storefront — but right now the catalog looks empty. That's expected. Products only appear once the store's search index has been built.

The search index is what powers the search and category pages a buyer sees. Until you run a full update, shoppers can't find any products. In this short setup you'll trigger that update from the Commerce app, wait for it to finish, and confirm products now show on the storefront.

A Deployed Storefront

Your headless React storefront is deployed and published (from Section 1), but products are not yet visible.

Commerce App Access

You can open the Commerce app from the App Launcher and manage the store's settings.

A Few Minutes

The index takes about 2–5 minutes to process after you start it. You can watch its status in the History table.

6 Simple Clicks

No code required — this is a guided, screenshot-by-screenshot walkthrough inside the Commerce store manager.

💡

The big picture: Deploy → build the search index → products appear. If a buyer reports “no products,” an un-built or stale index is almost always the cause.

2.1 Open the Commerce App

  1. Click the App Launcher (the nine-dot grid icon) in the top-left of the navigation bar.
  2. Type commerce in the search box.
  3. Under Apps, click Commerce.

2.2 Open the Store Workspace

  1. In the Commerce app's top navigation, click the Store tab (next to Home).
  2. This opens the store management workspace, where you can manage merchandising, pricing, and store settings.

2.3 Close Any Warning or Error Messages

  1. A canvas warning or error dialog may appear (for example, a “Your browsing session has ended or is invalid” message).
  2. Click the × (close) icon to dismiss it and continue.
💡

Safe to dismiss: These messages come from optional demo canvas components and don't affect building the search index. If the page fails to load entirely, re-login to Salesforce and reopen the Commerce app.

2.4 Go to Settings → Search

  1. Confirm the correct store is selected in the Store picker at the top of the left sidebar (e.g. SDO - B2B Commerce).
  2. In the left sidebar, expand Settings → and click Search.
  3. The Search Index tab opens, showing the update history and current status.

2.5 Click “Update” on the Top Right

  1. On the Search Index page, find the Update button in the top-right corner.
  2. Click Update to open the update options.
ℹ️

Note: The Automatic Updates toggle may be Off — that only controls incremental auto-updates. You can always trigger a manual update here.

2.6 Click on “Full Update”

  1. In the Update search index dialog, under Select a method, choose Full Update.
  2. Click Update to start indexing.
❗

Use Full Update — not Partial. A full update includes all store changes and is required when you create a new store or change search configurations. Partial updates only cover new or changed items.

2.7 Wait for Completion, Then Refresh

  1. Wait 2–5 minutes for the index to process. You don't need to keep the dialog open.
  2. In the History table on the Search Index page, watch the Status column change to Completed for your Full update. (Refresh the page if the status doesn't update on its own.)
  3. Open your storefront and hard refresh the page to load the freshly indexed catalog:
Mac: Cmd + Shift + R  •  Windows: Ctrl + Shift + R

Troubleshooting

Common issues and quick fixes if products still don't appear after indexing.

SymptomLikely cause & fix
Products still don't appear after refresh The index may still be processing. Confirm the History Status shows Completed (allow up to 5 minutes), then hard refresh again (Cmd/Ctrl + Shift + R) or try a private/incognito window.
Status shows Failed or Error Re-open Update and run a Full Update again. If it keeps failing, confirm the store has a catalog with products assigned and the buyer has entitlements.
“Products Updated” shows 0 No products are assigned to this store's catalog, price book, or entitlement policy. Assign products to the catalog, then re-run the Full Update.
Can't find Search under Settings Make sure you're in the Store workspace (Step 2.2) for the correct store — check the Store picker at the top-left — not the Commerce Home tab.
Warning / session dialog keeps reappearing Dismiss it with the × (Step 2.3). If the page won't load, re-login to Salesforce, reopen the Commerce app, and return to Settings → Search.
Only some products show A previous Partial update may have run. Run a Full Update to include the entire catalog and all configuration changes.
💡

Rule of thumb: Any time you change the store, catalog, or search configuration, re-run a Full Update and hard refresh the storefront to see the change.

✅ All set! Once the status is Completed and you've hard-refreshed, your products are discoverable on the storefront's search and category pages. Next, set up pricing so prices appear.

3 Set Up Pricing So Prices Appear

Configure and sync Salesforce Pricing so buyers can see product prices in your newly deployed B2B storefront.

Before you begin — why this step matters

Your products are deployed and searchable — but prices won't appear on the storefront until Salesforce Pricing is configured and the pricing data is synced. That's expected right after deployment.

In this walkthrough you'll set the store's default pricing recipe and pricing procedure, activate the procedure, and then sync pricing data. After the sync completes and you hard refresh, prices show on your product and category pages.

A Deployed & Indexed Storefront

Products are visible (from Sections 1 and 2), but their prices are not yet showing.

Setup Access

You can open Setup from the gear menu and edit Salesforce Pricing settings.

Commerce Pricing Defaults

The Commerce defaults ship with your org: recipe CommerceDefaultRecipe and the Cirrus - Commerce Default Pricing Procedure.

A Few Minutes

The pricing Sync runs in the background and takes a short while to finish before prices appear.

💡

The big picture: Configure pricing (Steps 1–4) → activate the pricing procedure (Steps 5–7) → sync pricing data (Steps 8–10) → refresh and prices appear.

3.1 Configure Pricing (Steps 1–4)

Step 1 — Click Gear Icon → Setup

  1. Click the gear icon (⚙️) in the top-right of the navigation bar.
  2. In the Setup Menu, click Setup. Setup opens for the current app.

Step 2 — Search for “Salesforce Pricing Setup”

  1. In the Setup Quick Find box (top-left), type Salesforce Pricing Setup.
  2. Under Feature Settings → Salesforce Pricing, click Salesforce Pricing Setup.

Step 3 — Select “CommerceDefaultRecipe”

  1. On the Set your basic Salesforce Pricing data page, find the Select a Pricing Recipe section.
  2. In the Pricing Recipe field, select CommerceDefaultRecipe.

Step 4 — Select “Cirrus - Commerce Default Pricing Procedure”

  1. In the Select a Pricing Procedure section, open the Select a default Pricing Procedure dropdown.
  2. Choose Cirrus - Commerce Default Pricing Procedure.

3.2 Activate the Procedure (Steps 5–7)

Step 5 — Click “View Pricing Procedures”

  1. Next to the Select a default Pricing Procedure field, click the View Pricing Procedures link.

Step 6 — Open “Cirrus - Commerce Default Pricing Procedure”

  1. On the pricing procedure page, find the Pricing Procedure Versions related list.
  2. Click the version name link Cirrus - Commerce Default Pricing Procedure to open it in the builder.

Step 7 — Click Activate

  1. In the pricing procedure builder toolbar (top-right), click Activate.
  2. A toast message confirms the version's status change. The procedure is now active and ready to sync.

3.3 Sync Pricing Data (Steps 8–10)

Step 8 — Go Back to Salesforce Pricing Setup

  1. Repeat Steps 1–2: click the gear icon → Setup, then open Salesforce Pricing Setup again.
  2. Your Pricing Recipe and Pricing Procedure selections from Steps 3–4 are retained.

Step 9 — Click “Sync” under Sync Pricing Data

  1. Scroll to the Sync Pricing Data section on the Salesforce Pricing Setup page.
  2. Click the Sync button on the right of that section.
ℹ️

The Sync button is disabled until both a Pricing Recipe and a default Pricing Procedure are selected (Steps 3–4).

Step 10 — Click “Confirm”

  1. In the “Are you sure you want to Sync?” dialog, click Confirm.
  2. The pricing sync now runs in the background.

3.4 Verify on the Storefront (Step 11)

Step 11 — After Syncing, Refresh the Storefront

  1. Wait for the pricing sync to complete. It runs in the background and finishes after a short time.
  2. Open your storefront and hard refresh the page:
Mac: Cmd + Shift + R  •  Windows: Ctrl + Shift + R

Troubleshooting

Common issues and quick fixes if prices still don't appear after syncing.

SymptomLikely cause & fix
Prices still don't appear after refresh The sync may still be running. Give it a few minutes, then hard refresh again (Cmd/Ctrl + Shift + R) or open the storefront in a private/incognito window.
Products show but price is blank or $0 Pricing data isn't synced yet, or the product has no price book entry. Confirm the product is in the store's price book, then re-run Sync (Steps 9–10).
Sync button is greyed out You must select both a Pricing Recipe and a default Pricing Procedure first. Complete Steps 3–4, then return to Sync Pricing Data.
Can't find “Salesforce Pricing Setup” It lives under Feature Settings → Salesforce Pricing in Setup. If it's missing, Salesforce Pricing may not be enabled — check with your workshop instructor.
Recipe or Procedure dropdown is empty The Commerce defaults (CommerceDefaultRecipe, Cirrus - Commerce Default Pricing Procedure) ship with the deployed store. Confirm the storefront was deployed successfully.
Activate is greyed out / already active The version may already be active — you can proceed to Sync. If needed, deactivate and re-activate to force a refresh of the procedure.
Sync fails or errors out Confirm the pricing procedure version is Active (Step 7), then retry the Sync. Re-running a Full sync is safe.
💡

Rule of thumb: Any time you change pricing configuration, re-run Sync Pricing Data and hard refresh the storefront to see the updated prices.

✅ Pricing is live! Once the sync has completed and you've hard-refreshed, product prices are visible on the storefront's product and category pages. Next, extend the PDP with a custom inventory component.

4 Build a Custom Inventory Availability Component

Extend your newly deployed B2B Commerce storefront with a real-time inventory component on the product detail page — built and deployed with AI-assisted development.

Before you begin — what's already set up

In the previous sections you deployed a B2B Commerce headless React storefront and made products and prices appear. Now you'll add a custom inventory availability component to the product detail page (PDP) — using Agentforce Vibes to write and deploy the React code for you.

Your workshop org has been pre-configured with everything the component needs. You will not write any Apex or touch permissions — you only build the front-end component.

Inventory Apex Class

An Apex REST class that fetches live inventory from Salesforce Order Management (OMS). It lives under /workshop/inventory and exposes GET /services/apexrest/inventory/availability?productId=.

Agentforce Vibes Skill

A pre-installed skill under .afv/skills/commerce-b2b-workshop-inventory that teaches the agent how to call the Apex class from a React component.

Buyer Permissions

Your buyer user already has the UIBundleApexAccess permission, so the storefront is allowed to invoke the Apex endpoint. No permission changes are needed.

A Deployed Storefront

A published headless storefront with product detail pages (from Section 1) that you can browse and refresh.

❗

Do not change the Apex class or permission sets. They are already correct. This workshop only adds a React component that calls the existing endpoint.

4.1 Build the Availability Component

Open the Agentforce Vibes chat in your storefront project and submit the prompt below. It tells the agent exactly what to build and how it should look and behave.

  1. Click into the Agentforce Vibes chat input field at the bottom of the chat panel.
  2. Copy and paste the following prompt exactly, then press Enter:
    ● Build component prompt
    Your org already has GET /services/apexrest/inventory/availability?productId= and your buyer has UIBundleApexAccess. Add a React availability component on the product detail page that calls it with the current product id. Show a colored bullet, the on-hand quantity in bold, and bold colored IN STOCK (green) or OUT OF STOCK (red). Below that, add a dropdown “Show Inventory Across All Locations” with comfortable spacing listing each location’s name and the same bullet / quantity / status. Use the Apex URL (not /commerce/webstores/...). On error, show “Availability unavailable”; do not crash the page. Do not change Apex or permission sets.

What the agent will build

  • A component on the PDP that calls the Apex endpoint with the current product id.
  • A colored bullet, the on-hand quantity in bold, and a bold IN STOCK / OUT OF STOCK label.
  • A “Show Inventory Across All Locations” dropdown that lists each location with its own bullet, quantity, and status.
  • Graceful error handling — it shows “Availability unavailable” instead of crashing the page.
⚠️

Watch the URL. The component must call the Apex REST URL /services/apexrest/inventory/availability — not a /commerce/webstores/... URL. If the agent generates the wrong URL, tell it: “Use the Apex REST URL, not the webstores API.”

4.2 Approve the Agent's Commands

While generating and wiring up the component, the agent may pause and ask for your approval before running commands against your org. This is expected.

  1. When a Run button appears in the chat, click it to let the agent proceed.
  2. Repeat for each pause — the agent may stop a few times as it reads project files, creates the component, and prepares the bundle.
  3. Read what each command does if you're curious, but for the workshop you can safely click Run to continue.
💡

Tip: Let the agent finish generating the component before moving to the build & deploy step. Wait for it to report that the component has been created.

4.3 Build & Deploy the Bundle

With the component created, ask the agent to build the React bundle and deploy it. Submit this prompt in the Agentforce Vibes chat:

● Build & deploy prompt
Build the React bundle, then deploy only the bundle to my default org.
  1. Press Enter to submit. The agent compiles the React app and deploys the updated bundle to your default org.
  2. Continue to click Run if the agent asks for approval during the build or deploy.
  3. Wait for the agent to confirm the deployment succeeded before opening the storefront.
💡

Tip: Deploying only the bundle keeps this step fast — there's no need to redeploy Apex, permissions, or site metadata, which are already in place.

4.4 View It on the Storefront

Now see your component live on the storefront.

  1. Open your storefront and navigate to any product detail page (PDP).
  2. Hard refresh the page to bypass the browser cache and load the new bundle:
    Mac: Cmd + Shift + R  •  Windows: Ctrl + Shift + R
  3. Look just below the price — your availability component should now appear.
⚠️

Don't see it yet? A single hard refresh usually isn't cached correctly the first time. Refresh once more, or open the PDP in a private/incognito window. See Troubleshooting below if it still doesn't show.

4.5 See the Result

Your product detail page should now show real-time inventory. Here's what a finished component looks like.

Aggregate availability

Directly under the price: a green bullet, the total on-hand quantity in bold, and IN STOCK — plus a “Show Inventory Across All Locations” toggle.

Inventory across all locations

Expanding the dropdown reveals each warehouse with its own bullet, on-hand quantity, and status — green IN STOCK or red OUT OF STOCK.

Troubleshooting

Common issues and quick fixes if your component doesn't appear or behave as expected.

SymptomLikely cause & fix
Component doesn't appear on the PDP The browser is serving a cached bundle. Hard refresh again (Cmd/Ctrl + Shift + R), or open the PDP in a private/incognito window. Confirm the agent reported a successful deploy.
Shows “Availability unavailable” The component called the endpoint but got an error. Verify it uses /services/apexrest/inventory/availability?productId= (the Apex URL, not /commerce/webstores/...). Re-prompt the agent to fix the URL, then rebuild and redeploy the bundle.
Wrong URL was generated Tell the agent: “Use the Apex REST URL /services/apexrest/inventory/availability, not the webstores API,” then run the build & deploy prompt again.
Permission / 401 / 403 error The buyer needs the UIBundleApexAccess permission — it is pre-assigned in your workshop org. Do not change permission sets yourself; ask your workshop instructor for help if the error persists.
Quantities show 0 for every location That product may have no OMS inventory loaded. Try a different product's PDP (e.g. the reference battery). Zeros correctly render as red OUT OF STOCK — that's expected behavior, not a bug.
Build or deploy fails Read the error in the chat and ask the agent to retry: “The build failed with this error — please fix it and redeploy the bundle.” Ensure you deployed to your default org.
Old version keeps showing Clear the site cache: hard refresh, try incognito, or append ?cache=0 to the PDP URL. Confirm the latest bundle actually deployed (re-run the deploy prompt).
Dropdown looks cramped Re-prompt the agent: “Add comfortable spacing between location rows in the availability dropdown,” then rebuild and redeploy.
💡

When in doubt, ask the agent. Paste the exact error or describe what you see and ask Agentforce Vibes to diagnose and fix it — then rebuild and redeploy the bundle.

✅ Nicely done! You've built and deployed a custom React component that reads live OMS inventory through your org's Apex REST endpoint — completing the full journey: deploy → search index → pricing → custom component.
